# 🎃 Patisson Game 2.0

Полная переработка [Patisson Game](https://github.com/fedor655/Patisson-Game) —
та же ферма с патиссонами, но на собственном движке поверх
[**Panda3D**](https://www.panda3d.org/) с физически корректным освещением,
процедурным миром и живыми жителями.

> Ветка `patisson-2.0`. Оригинальная игра Богдана на Ursina — в ветке
> [`main`](https://github.com/fedor655/Patisson-Game/tree/main).

## 🚀 Запуск

```bash
pip install -r requirements.txt
python -m patisson2
```

Всё. **Ресурсы не нужно нигде скачивать** — все 3D-модели лежат в репозитории
(`assets/models`, ~6 МБ), а земля, трава, вода, небо, облака и весь звук
генерируются кодом. Это главное отличие от 1.0, где игре требовался
установщик на 650 МБ.

При первом запуске игра около секунды генерирует звуковые эффекты в
`~/.patisson2/audio/`, а музыку дорисовывает в фоне.

Пресеты качества:

```bash
python -m patisson2 --low
python -m patisson2 --medium
python -m patisson2 --high
python -m patisson2 --ultra
python -m patisson2 --fullscreen
```

Ключ пресета **перебивает сохранённые настройки**: раньше он их не перебивал —
`main()` собирал конфиг по пресету, а приложение тут же перезаписывало его тем,
что лежало в `settings.json`, и `--low` запускался с включёнными SSAO, лучами
солнца и тенями 2048. Менялось от пресета только количество травы.

Пересобрать модели после правок в генераторе:

```bash
python -m patisson2.tools.make_assets
```

Пересобрать иконку игры (`assets/icon.ico`) — она **рендерится из спелого
патиссона самой игры**, а не рисуется отдельно, поэтому не может изобразить
то, чего в игре нет:

```bash
python -m patisson2.tools.make_icon
```

Снять скриншоты (игра рендерится offscreen, окно не нужно):

```bash
python -m patisson2.tools.shots
```

Прогнать все действия игрока разом — 88 проверок, от вспашки до загрузки
сохранения. Тоже без окна, выходит с ненулевым кодом, если что-то сломалось.
**Шестнадцать действий он выполняет клавишей**, встав и прицелившись туда же,
куда встал бы игрок, и проверяет, что мир изменился, — а не что вызов не упал.
Именно поэтому мёртвая прополка и прожила так долго: тест дёргал `Farm.weed()`
напрямую, минуя клавишу, которая ничего не делала.

Отдельная проверка обходит **все таблицы объявлений** и требует, чтобы каждая
строка была и произведена, и потреблена: достижение с `unlock()`, шаг обучения
с `teach()`, вид задания с `record()`, товар лавки, который где-то тратится,
тир инструмента, который что-то меняет, ингредиент рецепта, который где-то
берётся, звук, который есть в банке. Три бага подряд имели именно эту форму —
интерфейс обещал то, чего за ним нет:

```bash
python -m patisson2.tools.smoke
```

### Игра без движка

Вся симуляция — грядки, погода, вредители, живность, жители, экономика —
**работает без Panda3D**. Логика ходит через `patisson2/game/view.py`: там, где
есть сцена, он отдаёт настоящий узел, а там, где её нет, — узел, который молча
принимает «подвинься», «покрасься», «исчезни» и ничего не рисует. Поэтому в
коде симуляции нет ни одной ветки «а есть ли у нас экран».

Это фундамент сразу для двух вещей: выделенного сервера, который держит мир для
всех играющих, и версии для телефона, которой останется написать только
отрисовку. Проверить можно прямо сейчас — Panda3D блокируется на уровне
импорта, так что пройти случайно нельзя:

```bash
python -m patisson2.tools.headless_check
```

### Совместная игра (в работе)

Ферму можно держать на сервере и работать на ней вдвоём. Сервер владеет миром —
грядками, часами, погодой, воронами и кошельком, — а клиенты присылают только
то, что **хотят** сделать; что произошло на самом деле, решает он. Иначе две
машины, считающие рост урожая независимо, за день разъезжаются, и грядка,
спелая у одного, у другого остаётся ростком.

```bash
python -m patisson2.net.server --port 7777
```

Мир периодически пишется на диск **и читается обратно при запуске**: люди
оставляют урожай в земле и рассчитывают найти его на следующей неделе. Сервер
писал сохранение с самого начала, но никогда его не открывал, поэтому каждый
перезапуск молча выдавал всем новую ферму — это хуже, чем не сохранять вовсе,
потому что выглядит как будто работает.

Амбар на такой ферме общий, и правило простое: **тратится только то, что
сработало**. Списание шло до проверки — кто не успел посадить грядку
первым, платил семечком из общего амбара за то, чего не произошло.

Общий амбар клиенты и видят общим: сервер шлёт его, когда он меняется,
а не один раз в дверях. Иначе панель предлагает «Патиссон x3» на ферме,
где последнее семечко ушло в землю час назад, и нажатие отклоняется
молча. Про пугало сервер отвечает не числом, а двумя вопросами — пугает
ли оно ещё и есть ли что чинить: иначе каждый клиент выдумывает свой
порог, а ферма при нажатии применяет свой.

Серверу не нужна видеокарта: он поднимает ту же симуляцию без Panda3D. Мир
периодически пишется на диск, а **пока на ферме никого нет, время стоит** — это
не оптимизация, а следствие наблюдения: оставленный тикать пустой сервер за
полтора дня терял пугало и вороны склёвывали каждую спелую грядку.

В игре сеть включается пунктом **«Играть по сети»** в главном меню: там
вводятся адрес фермы и имя, и оба запоминаются в `~/.patisson2/settings.json`.
Сначала строка жила только в этом файле — то есть единственная возможность,
которой нужен чужой адрес, не работала без текстового редактора. На чужой ферме локальная симуляция останавливается: мир уже
считается там, и считать его ещё раз здесь — значит получить два ответа на один
вопрос. Все действия игрока — включая правый клик, который дольше всех
оставался единственным нажатием, не покидавшим машину, — становятся
просьбами, а остальные видны фигурками с
именем над головой — и списком в углу экрана, где рядом с каждым именем
написано, сколько до него метров. Имя над головой помогает, только пока
голова в кадре, а ферма в кадр не помещается: сосед с той же вероятностью
стоит за амбаром, что и перед вами. Сам список снимается тем же способом,
что и остальные скриншоты, только с настоящим сервером на локальном порту:

```bash
python -X utf8 -m patisson2.tools.netshot
```

Проверка поднимает настоящий сервер на локальном порту и говорит с ним по
настоящему сокету — без заглушек, потому что подделка скрыла бы ровно то, что
стоит проверять: рукопожатие, отказ устаревшему клиенту словами, снимок мира,
чужой полив на своём экране, общий кошелёк, обрыв связи и покой пустой фермы:

```bash
python -m patisson2.tools.net_check
```

### Телефон (в работе)

К той же ферме можно подключиться с телефона. Мобильный клиент — **тонкий**:
он не тянет ни Panda3D, ни numpy, ни саму игру, а знает ровно одно — формат
сообщений. Мир считается на сервере, поэтому телефону остаётся рисовать вид
сверху и передавать касания. Ради этого протокол с самого начала сделан на
обычных сокетах и JSON.

```bash
pip install kivy
python -m patisson2.mobile.main 127.0.0.1:7777 Имя
```

APK собирается на GitHub Actions (`.github/workflows/apk.yml`), а не на машине
игрока: `python-for-android` тянет Android SDK и NDK на много гигабайт и
компилирует Python под ARM — это работа для отдельной сборочной машины.
В APK едут ровно два файла, и отдельная проверка следит, чтобы туда не
пробрался движок:

```bash
python android/check_thin.py
```

Тап по грядке = выбранный инструмент (лейка, мотыга, семена, корзина,
удобрение), рядом с точками игроков — их имена, отдельными кнопками продажа
урожая и починка пугала. Телефон теряет сеть постоянно — в лифте, в метро, на
даче, — поэтому при обрыве клиент говорит, что случилось, и сам пробует
вернуться каждые пять секунд. Сверху
часы, сезон, погода и общий кошелёк, снизу — что происходит на ферме. Сборка
APK — следующий шаг: `python-for-android` собирается только на Linux, поэтому
пойдёт на сервере, а не на Windows.

### Требования

Python 3.10+, видеокарта с OpenGL 4.3. Разрабатывалось и проверялось на
GeForce RTX 3070 Laptop (OpenGL 4.6): **90–110 fps в 1600×900** на пресете по
умолчанию, со звуком и погодой. Разброс — это троттлинг ноутбука, а не разница
в сцене: дождь и снег стоят меньше миллисекунды. **Долгая сессия ничего не
накапливает**: за 23 игровых дня с сотней открытий панелей, посадок, сборов,
сохранений и загрузок число узлов сцены осталось ровно 331, узлов интерфейса —
103, счётчик объектов Python не сдвинулся. Если тормозит — `--low`:
SSAO и лучи солнца выключаются, тени падают до 1024, травы вчетверо меньше,
дальность прорисовки 260 м вместо 420. Насколько это добавляет кадров, честно
сказать не могу: offscreen-замер не ждёт видеокарту и на всех пресетах даёт
одно и то же, а мерить с чтением кадра обратно — значит мерить чтение.

## 🌱 Что нового по сравнению с 1.0

### Движок и графика

Всё написано с нуля на Panda3D + GLSL 4.60, без готовых пайплайнов:

- **PBR-освещение** (Cook-Torrance GGX) с корректным ambient-членом (split-sum).
- **Атмосфера с однократным рассеянием** (Рэлей + Ми) считается каждый кадр в
  маленькую равнопромежуточную таблицу неба. Из неё берётся и рассеянный свет,
  и воздушная перспектива — поэтому освещение сцены физически согласовано с тем
  небом, которое видно в кадре, в любое время суток.
- **Тени солнца**: карта 2048² на радиус 48 м (4,7 см на тексель), PCF,
  смещение вдоль нормали, кадр следует за игроком и привязан к сетке
  текселей — тени не «плывут» при ходьбе.
- **Постобработка**: SSAO, bloom, объёмные лучи солнца, тонемаппинг ACES,
  цветокоррекция, виньетка, зерно, FXAA.
- **Процедурный ландшафт**: сетка сгущается к центру, поэтому у фермы
  треугольники метрового масштаба, а по краю мира поднимаются холмы — границы
  карты не видно.
- **Трава на GPU**: одна травинка, ~170 000 инстансов (`--low` — 42 500,
  `--ultra` — 340 000), позиция, наклон, размер и
  цвет каждой считаются в вершинном шейдере из номера инстанса. Трава знает
  высоту земли, уклон, воду и вскопанные грядки. *Раньше весь этот ковёр был
  приварен к камере*: базой травинки было «центр + свой сдвиг», и при каждом
  шаге все 170 тысяч травинок скользили по земле вместе с игроком — второй баг,
  найденный живым игроком. Теперь каждая травинка владеет фиксированной точкой
  мира в повторяющейся плитке со стороной в два радиуса, а рисуется ближайшее
  к игроку повторение; smoke-проверка рендерит один и тот же кадр с центром,
  сдвинутым на два метра, и требует, чтобы газон не сдвинулся (средняя разность
  0,03 против 7,4 у старого шейдера — и на нём она падает).
- **Деревья качаются вразнобой.** Статика ради батчинга сплющена в тайлы по
  40 м, а фаза ветра бралась из начала узла — один model matrix на тайл, и вся
  роща махала под один метроном (игрок заметил). Теперь фаза считается из
  мировой позиции самой вершины: низкая пространственная частота держит одну
  крону единым целым, а соседние деревья расходятся. Проверка меряет это
  пикселями: две кроны рендерятся с шагом 0,15 с в пяти замороженных моментах,
  отношение их сдвигов при общей фазе — константа (разброс 0,0003 на старом
  шейдере), при своих — гуляет (1,07); на старом шейдере проверка падает.
- **Вода**: волны Герстнера, **зеркальное отражение мира** (сцена рисуется
  второй раз камерой, отражённой сквозь плоскость воды, и шейдер берёт результат
  по собственной экранной координате фрагмента), поглощение по реальной глубине
  (читается высота дна), каустики, пена у берега. Проход включается только когда
  игрок рядом с прудом и стоит 0,3 мс.
- **Сутки и времена года**: положение солнца считается по часовому углу и
  склонению, зимой день короче. Небо, цвет света, экспозиция, цвет травы и
  деревьев следуют за сезоном.

### 🔊 Звук: тоже сгенерирован кодом

Записанных звуков в игре нет ни одного. В репозитории лежит **синтезатор**
(`patisson2/audio/`) — осцилляторы, огибающие, фильтры, ревербератор — и
описания всех звуков как функций. При первом запуске игра рендерит из них
35 файлов в кэш `~/.patisson2/audio/`:

- **25 эффектов**: удар мотыги, полив, посадка, срыв плода, заброс удочки,
  всплеск, монеты, скрип колодца, куры, корова, гром, шаги (четыре варианта с
  разбросом высоты тона), клики интерфейса, фанфара достижения, а также
  три разные птичьи трели, лягушка, сова и карканье вороны.
  *Птицы пели «по-цифровому»* — и точно: каждая была голым синус-свипом, у
  которого 97 % энергии сидит в одной спектральной линии, а фоновые птицы дня
  вообще без единой гармоники. У свистка теперь есть горло: быстрое мелкое
  вибрато, вторая и третья гармоники, дыхание шумом и не щёлкающая атака —
  доля энергии в основном тоне упала до 0,84–0,90, и проверка «у птиц есть
  голос» на старом синтезе падает.
- **6 фоновых слоёв**: птицы днём, сверчки ночью, ветер, дождь, плеск воды и
  шелест листвы — все бесшовно зациклены и плавно перетекают друг в друга.
  *Ветер раньше звучал как морской прибой* (слова игрока): его огибающей были
  два чистых синуса 0,07 и 0,031 Гц с глубиной почти 70 % поверх низкого гула —
  накат волны каждые двенадцать секунд. Теперь огибающая — медленный
  сглаженный шум малой глубины, порывы больше подсвечивают шипение листвы, чем
  гул. Проверка меряет это по сгенерированной волне: глубина модуляции упала с
  0,69 до 0,14, сильнейший пик спектра огибающей — с 0,47 до 0,06, и на старом
  синтезе она падает («ветер дышит как прибой»).
- **4 музыкальные темы** (утро, день, вечер, ночь) по 65 секунд — аккордовая
  прогрессия, арпеджио, бас и мелодия из пентатоники, с ревербератором.
  Музыка сменяется по часам с плавным кроссфейдом.

Эффекты и фон генерируются за секунду, музыка — в фоновом потоке, поэтому
запуск не ждёт её. Так весь звук стоит репозиторию несколько килобайт кода
вместо 15 МБ WAV-файлов.

**Звучит то, что рядом.** Первые четыре слоя включаются по часам и погоде, но
плеск воды и шелест листвы — по тому, где стоит игрок: пруд слышно с тридцати
метров и всё громче к берегу, листва набирает силу от числа деревьев вокруг.
Под крышей оба слоя выключаются вместе с птицами — раньше микшер вообще не
знал, что игрок зашёл в дом.

Живность тоже перестала быть безадресной. Раз в 5–13 секунд игра выбирает,
кому подать голос, взвешивая варианты по часу, сезону и погоде — и **молчание
участвует в этом розыгрыше наравне с остальными**, иначе зимний полдень звучал
бы ровно так же оживлённо, как летний. Птица поёт из конкретного дерева (звук
идёт из кроны, а не от ствола), сова — из леса и только ночью, лягушка — с того
берега пруда, к которому игрок ближе. В дождь не поёт никто. Ворона каркает,
когда садится на грядку и когда её спугнули.

### 🔦 Фоторежим: настоящая трассировка лучей

Клавиша **`P`**. Игра снимает геометрию сцены прямо из графа, строит по ней BVH,
загружает всё в видеопамять и запускает **compute-шейдер, который трассирует
пути** — с мягкими тенями от солнечного диска, глобальным освещением на
несколько отражений и русской рулеткой. Картинка накапливается прогрессивно,
пока не станет чистой (обычно несколько секунд).

Это не постэффект «под RTX», а честный path tracer: то, что растеризатор
приближает (SSAO, тени из карты, ambient), здесь считается по-настоящему.
Нужен OpenGL 4.3+ с compute-шейдерами; на RTX 3070 сцена из ~260 000
треугольников доходит до чистой картинки примерно за 5 секунд.

### Мир

- 51 модель, **все сгенерированы кодом** (`patisson2/tools/make_assets.py`):
  дом, амбар, колодец, прилавок, забор, пугало, ящики, бочки, фонари, деревья
  четырёх видов, кусты, камни, камыш, кувшинки, цветы, куры, корова, кот,
  бабочки, рыба, патиссон на четырёх стадиях роста и жители,
  разобранные на части для анимации.
- **Дом и амбар можно зайти внутрь.** У обоих настоящий дверной проём, пол,
  потолок и обстановка: кровать, стол со табуретами, полка с банками и топящийся
  очаг в доме; стойла, кормушка и сено в амбаре. В кровати можно **лечь спать** —
  до шести утра, с полным восстановлением сил.
- **Стены, стволы, заборы, ящики и бочки теперь твёрдые.** Раньше игрок проходил сквозь всё,
  кроме крутых склонов и глубокой воды. Препятствия лежат в равномерной сетке и
  выталкивают игрока наружу; дверной проём — это просто отсутствие препятствия.
- **В колодце стоит вода.** Каменный венец был открытым кольцом поверх обычной
  земли: заглянув внутрь, игрок видел газон, растущий на дне «колодца». Теперь
  под венцом тёмная стоячая гладь, а трава внутри кольца выключена через маску.
  Проверка рендерит взгляд в колодец, проецирует точку глади в пиксели кадра и
  требует воду, а не зелень, — на старой модели она падает («в колодце трава,
  а не вода»).
- **Фонари висят на столбах.** Уличные фонари ставились на высоте 1,35 м, и под
  ними не было ничего — лампы просто парили в воздухе, одну такую игрок
  сфотографировал у стены дома. Теперь у каждого фонаря деревянный столб с
  кронштейном и крюком, столб твёрдый, а свет остался там, где стекло. Проверка
  щупает сетку столкновений под каждым уличным фонарём и требует опоры — на
  старой расстановке она падает («фонарь (2.0, -7.0) висит в воздухе»).
- **Обучение, которое смотрит, а не рассказывает.** Десять шагов в углу экрана
  отмечаются сами, когда вы делаете дело: вскопали грядку, набрали воды, продали
  урожай, открыли карту. Ни одного окна «нажмите OK» — шаг засчитывается по
  событию, которое игра и так уже отправляет. Из паузы обучение отключается,
  а его прогресс попадает в сохранение. *Пройти его было нельзя.* Девятый шаг —
  «загляните в лавку» — не отправлял никто: обучение намертво вставало на 8/10,
  десятый шаг был недостижим, панель не уходила с экрана никогда, и надпись
  «Обучение пройдено. Ферма ваша.» не появлялась ни у кого.
- **На панели инструментов виден тир.** «1 Мотыга II», «1 Мотыга III» — купив
  мотыгу за 520 монет, игрок раньше не видел на панели ровно никакой разницы.
  *Подписи при этом сидели ниже центра своих плашек* («кнопки немного не по
  центру» — игрок), а «3 Патиссон x3» была шире плашки и торчала с обеих
  сторон. Теперь базовая линия выводится из центра плашки, длинные подписи
  ужимаются по измеренным глифам, и проверка «подписи инструментов по центру»
  на старой вёрстке падает.
- **Автосохранение и три слота.** Игра сама пишется каждые две минуты, на
  рассвете при пробуждении и при выходе в меню — в отдельный слот, который
  никогда не затирает ручное сохранение. Ручных слотов три; в меню видно, что в
  каждом: день, сезон, деньги, сколько наиграно. Запись идёт во временный файл
  и подменяется одним движением, поэтому падение посреди сохранения не может
  оставить обрубок на месте живого сейва.
- **Сохраняется всё, а не почти всё.** Тест в `smoke.py` строит мир с
  приметными значениями, записывает его, ломает живое состояние до неузнаваемости,
  загружает обратно и **сверяет 21 группу полей**: деньги, инвентарь, тиры
  инструментов, достижения, задания, каждую грядку с её ростом, водой,
  сорняками и гнилью, живность, пугало, обучение, часы, позицию игрока, с кем
  вы уже знакомы — и погоду. Погода как раз и не сохранялась: игра, записанная
  под дождём, загружалась в ясный день, а жители выходили из-под навесов.
- **Испорченный сейв не роняет игру.** Файл лежит там, где его может
  отредактировать игрок, побить диск или записать сборка постарше, — поэтому
  ничего после чтения не считает, что поле того типа, каким его записали.
  Раньше шесть из десяти повреждённых файлов роняли загрузку с исключением, а
  `describe()` падал вместе с ней — то есть **один битый слот делал главное
  меню неоткрываемым**. Теперь нечитаемый слот так и подписан: «повреждено».
- **Недоступный для записи диск не мешает играть.** Если домашнюю папку нельзя
  писать (заблокированный профиль, полный диск), игра раньше вообще не
  запускалась: кэш звуков не создавался, и исключение вылетало из конструктора.
  Теперь звук просто выключается с сообщением в консоль, а игра идёт. `F5` в
  такой ситуации отвечает «Не удалось сохранить: …» вместо падения — момент,
  когда игрок жмёт «сохранить», это последнее место, где уместен traceback.
  Отсутствующая модель — наоборот, останавливает запуск сразу и говорит, что
  делать: `python -m patisson2.tools.make_assets`. Это сломанная установка, и
  прятать её за невидимой бочкой было бы хуже.
- **Клавиши переназначаются, и есть геймпад.** Ни одна часть игры больше не
  слушает клавишу напрямую — она просит *действие*, а раскладка решает, что его
  вызывает. Восемнадцать действий переназначаются на экране управления: выбрали
  строку, нажали Enter, нажали клавишу. Занять клавишу, уже занятую другим
  действием, можно — они меняются местами, а не остаются вдвоём на одной;
  клавиши интерфейса (Esc, Enter, стрелки, 1–5) защищены. Раскладка живёт в
  настройках и переживает перезапуск. Геймпад подхватывается сам: стики — ходьба
  и обзор, лицевые кнопки — прыжок, действие, удобрение, смена культуры.
  *Код геймпада написан по API Panda3D, но проверить его на живом контроллере
  не на чем — на машине разработки его нет; отсутствие устройства ни на что не
  влияет.*
- **Настройки прямо в игре (`O`).** Качество (низкое / среднее / высокое /
  ультра), тени, SSAO, свечение, лучи солнца, плотность травы и три громкости —
  всё применяется сразу, без перезапуска: карта теней пересоздаётся, проход
  затенения выключается целиком, а не просто игнорируется, трава меняет число
  инстансов на лету. Выбор пишется в `~/.patisson2/settings.json` и подхватывается
  при следующем запуске *до* сборки сцены, поэтому первый кадр уже такой, как
  просили. *Служебная подпись внизу печаталась поперёк последней строки меню*
  («немного текст пересекается» — игрок): она стояла на захардкоженном `y`, а
  десятая строка при настоящем межстрочном интервале шрифта доставала ниже.
  Теперь подпись вешается под измеренный низ меню на обеих страницах, и
  проверка вёрстки на старом коде падает.
- **Карта на `Tab`.** Рисуется из того же поля высот, что читает шейдер земли,
  и **из тех же списков, по которым расставлен мир**: каждое дерево из леса,
  оба дома со своими поворотами, грядки. Разойтись с миром она поэтому не
  может. Раньше карта охватывала 240 метров и шла по одному лишь рельефу —
  ферма была миниатюрой посреди пустого зелёного поля; теперь 144 метра, и
  видно, где лес, где пруд, где дом. Выбранное место подписано прямо на карте:
  восемь одинаковых квадратиков не говорили, который из них какой.
  Поверх — метки построек, живые метки жителей и ваша со стрелкой направления.
  Отсюда же можно **перейти к любому месту**: дорога отнимает ровно столько
  игрового времени, сколько заняла бы пешком, и тратит силы — это удобство, а не
  телепорт. Приходит игрок **рядом с меткой, а не в неё**: метка показывает сам
  предмет — колодец, прилавок, середину пруда, — то есть ровно те места, где
  стоять нельзя. Раньше переход к колодцу ставил игрока внутрь сруба, к
  прилавку — внутрь прилавка, а к пруду — на три с половиной метра под воду.
  Точка прибытия теперь вычисляется: сперва наружу из воды, потом наружу из
  всего твёрдого.
- **Вода растит, удобрение ускоряет.** Политая грядка доживает до урожая сама:
  патиссон за 4,8 дня, морковь за 2,9, томат 3,8, пшеница 2,3, тыква 6,8.
  Удобрение снимает с этого срока почти 40 % (2,9 / 1,8 / 2,4 / 1,4 / 4,1) и
  добавляет лишний плод к урожаю — то есть делает ровно то, что написано на
  ценнике: «питание для растения». *Раньше оно было аппаратом жизнеобеспечения.*
  Выживание грядки требовало и воды, и еды, а посадка давала 0,3 еды при расходе
  0,85 в день — через восемь часов грядка начинала голодать. Игрок, честно
  таскавший воду, но не купивший удобрение, смотрел, как всё до единого
  посаженное вянет до нуля, — и предупреждение при этом винило полив. В стартовом
  инвентаре одно удобрение, а первое задание — «вырасти патиссон», на который их
  требовалось пять. *Выигрышную тактику игра при этом держала в секрете*: один
  мешок перед самым сбором окупается (лишний плод за 6 монет), а кормить грядку
  весь сезон — убыток. Теперь это написано в справочнике (порог сытости
  печатается из той же константы, которую читает `harvest()`), и жители сами
  подсказывают, когда почти спелая грядка недокормлена, — проверка «трюк с
  удобрением объяснён» падает, если правило исчезнет из обоих мест.
- **У каждой культуры есть своя ниша.** Чем дольше культура занимает грядку и
  чем меньше у неё сезонов, тем лучше она должна платить: пшеница 6,6 мон./день
  (2,3 дн., три сезона) → морковь 7,7 → патиссон 8,7 → томат 9,4 (два сезона) →
  тыква 10,7 (6,7 дн., только осень). *Раньше это был не выбор, а рейтинг:*
  четыре культуры из пяти проигрывали другой культуре **одновременно** по
  прибыли, по времени и по числу сезонов — сажать имело смысл только томат и
  пшеницу. Патиссон, которым названа игра, проигрывал пшенице по всем трём осям
  сразу: 8,7 против 13,1 монеты в день, 4,8 дня против 2,3, те же три сезона.
  Теперь этого не допускает проверка `у каждой культуры своя ниша`: она
  перебирает все пары и падает, если хоть одну грядку незачем занимать.
- **Справочник называет сроки, которые можно получить.** Обе цифры в альманахе
  не записаны в таблицу, а **проинтегрированы из той же формулы роста**, по
  которой живёт грядка, — и тест выращивает настоящую грядку, чтобы это
  доказать. Раньше страница печатала поле `grow_days`, а это параметр скорости,
  а не срок: его достигает только грядка, которую держат на полной воде и полном
  питании. Справочник обещал патиссон за «2 дн.», политый растёт 4,8, удобренный
  2,9. Заодно проверяется, что колонки журнала не наезжают друг на друга: он уже
  один раз переполнялся, а строка со сроком как раз стала длиннее.
- **Грядка — это земля, а не краска.** Вскопанная грядка была тёмным кругом,
  нарисованным в маску террейна: при разрешении маски ~3,5 пикселя на метр это
  мыльное пятно, и игрок его так и назвал — «низкая полигональность у грядок».
  Теперь у каждой грядки модель: приподнятая плита земли с четырьмя гребнями
  борозд (по 60 треугольников), ростки стоят на её поверхности, а не под ней.
  Проверка «грядки из земли, не из краски» меряет высоту и размер модели и
  падает на старом коде.
- **За грядками надо ходить, а не только поливать.** Сорняки лезут тем быстрее,
  чем сырее и сытнее земля: сперва тормозят рост, потом начинают пить воду сами.
  Убираются мотыгой — по грядке с посадкой тоже, ведь сорняки для того и растут,
  чтобы душить то, что посажено. В сырой земле заводится гниль — рост встаёт,
  здоровье падает, лечится золой из лавки. А на спелые грядки прилетают вороны:
  кружат, садятся и склёвывают урожай, если не подойти и не спугнуть.
  *Прополка вообще не работала.* Её ветка стояла внутри «если грядки рядом нет»
  и потом искала заросшую грядку в **меньшем** радиусе, чем тот, которым грядку
  только что нашли, — то есть выполниться не могла никогда. Игра писала
  «[E] Прополоть · Сорняки: 80%», игрок жал `E`, и не происходило ничего: ни
  прополки, ни звука, ни сообщения. Вместе с ней лежал и счётчик достижения
  «прополоть двадцать грядок» — он к тому же не сохранялся.
- **У пугала появилась работа.** Оно защищает **весь огород**, но треплется со
  временем и вдвое быстрее под дождём. Развалившееся пугало ворон не пугает —
  подойдите и поправьте. Радиус защиты не выбран на глаз, а **считается по
  расположению грядок**: раньше это были 11 метров против огорода, дальний угол
  которого в 14,2 м, — пугало прикрывало 13 грядок из 24, а переставить его
  игрок не может. Половина фермы была лотереей, которую нельзя выиграть никаким
  уходом.
- **Инструменты растут в три уровня.** Каждый уровень меняет не число, а
  поведение: мотыга копает 1 → 3 → 9 грядок за взмах, лейка вмещает 8 → 18 → 34
  воды и мочит 1 → 5 → 9 грядок за нажатие, удочка ускоряет клёв, расширяет окно
  подсечки, замедляет метку и повышает шанс на редкую рыбу, корзина добавляет
  плоды к урожаю и +25 % к цене продажи. Лавка всегда показывает следующую
  ступень. **Каждое из этих обещаний проверяется тестом**, потому что
  предложение в лавке — это договор с игроком, а за ним стоит число, которое
  читает совсем другой код: корзина даёт 1 → 2 → 3 плода и поднимает цену
  четырёх патиссонов с 208 до 260 монет, а клёв ускоряется с 3,1 до 1,4 секунды.
  *У золотой лейки поведения не было вовсе.* Второй уровень менял только объём
  бака — единственное улучшение в лавке, которое двигало число и ничего больше,
  хотя класс `Upgrades` прямо обещает обратное. Полить 24 грядки как следует —
  это около 82 доз воды в день; лейка за 220 монет убирала из этой рутины 6
  действий из 93. Теперь 93 → 21 → 12.
- **Подсказки не проходят сквозь стены.** Радиусы взаимодействия — круглые
  числа, выбранные на глаз, а стены — то место, где мир на самом деле
  кончается. Котёл стоит примерно в двух метрах от дома, а его подсказка
  доставала на четыре с половиной: **201 точка внутри дома**, где можно стоять,
  предлагала «[K] Готовить» у котла по ту сторону стены. Теперь условие берётся
  не из радиуса, а из планировки: объект и игрок должны быть по одну сторону
  стен. Заодно у котла вообще не было столкновения — в него можно было встать.
  Проверка обходит все точки вокруг прилавка, котла, колодца и кровати и
  спрашивает **саму игру**, а не повторяет расчёт расстояния: первая версия
  этой проверки расстояние повторила и продолжала рапортовать о баге уже после
  того, как он был исправлен.
- **Цена улучшения отвечает за то, что оно даёт.** Корзина — единственный
  инструмент, который печатает монеты, а не экономит труд, и печатает много:
  лишний плод с каждой грядки больше чем удваивает доход фермы (256 → 570 мон.
  в день). Стоила она при этом 160 — дешевле всего в лавке — и окупалась за
  полдня, так что вопроса «что купить первым» не существовало, а три остальных
  инструмента были декорацией. Теперь 340 и 900, и проверка
  `улучшения не окупаются мгновенно` падает, если какое-нибудь улучшение снова
  начнёт возвращать свою цену быстрее чем за игровой день.
- **Живность**: куры бродят у амбара, коровы пасутся, кот гуляет у дома,
  бабочки летают над грядками. *Бабочки при этом крутились вокруг своей оси* —
  курс им задавал таймер, тридцать градусов в секунду независимо от полёта.
  Теперь нос смотрит туда, куда ведёт траектория (курс — полярный угол
  скорости), а проверка гоняет живых бабочек и сверяет нос с фактическим
  смещением: на старом коде расхождение доходило до 178°.
- **Три жителя** с распорядком дня: Богдан работает на грядках, потом стоит за
  прилавком и уходит домой спать; Марина торгует и ходит рыбачить; Пётр кормит
  кур и пасёт коров. Каждая точка расписания проверяется тестом: **на суше, не
  на круче, и до неё успевают дойти**. У Марины «рыбачит у пруда» было ровно
  центром пруда — она шестую часть каждого дня стояла на дне, с водой выше
  головы, под подписью, что она рядом с ним. Теперь это берег в 8,5 м от
  центра, откуда сама игра предлагает забросить удочку.
- **Они говорят про то, что происходит сейчас.** Раньше у каждого был список из
  четырёх-пяти реплик, которые он зачитывал по кругу: Богдан советовал поливать
  патиссоны посреди снегопада и повторял это на сороковой день, когда в лавке
  давно было золото. Теперь реплика принадлежит **теме**, а тема знает, когда
  она уместна: ворона на грядке, поспевший урожай, гниль, заросшие сорняками
  грядки, первая невскопанная земля, пустой кошелёк, неоконченное задание,
  сезон, час, дождь. Все подходящие темы участвуют во взвешенном розыгрыше —
  срочная обычно побеждает, но не запирает остальные насмерть. Каждый житель
  помнит четыре последние свои реплики и не повторяется. 21 тема, 138 реплик,
  плюс отдельное приветствие при первом знакомстве — кто с кем уже знаком,
  пишется в сохранение.
- **Жители не любят мокнуть.** Как только начинается дождь или снег, распорядок
  дня отменяется: каждый идёт под ближайшую крышу — Богдан домой, Марина под
  навес лавки, Пётр в амбар — и торопится туда быстрее обычного, сгорбившись и
  прижав руки. Пока пережидают, и говорят они о другом. Прояснилось — вернулись
  к делам.
- **У жителей есть лица и походка.** Каждый собран в игре из отдельных частей —
  таз, голова, две руки, две ноги, — и поза считается процедурно: ноги и руки
  ходят в противофазе, таз приподнимается на каждый шаг и кренится в него, а
  фаза шага берётся из пройденного расстояния, а не из времени, поэтому ступни
  не скользят. Голова поворачивается к игроку, когда он рядом, а иначе изредка
  оглядывается по сторонам. На месте — дыхание, за работой — наклон вперёд.
- **Погода видна**: дождь и снег — десятки тысяч частиц, размещаемых целиком в
  вершинном шейдере внутри объёма, который едет за камерой и заворачивается по
  мировой сетке, так что при ходьбе ничего не «выпрыгивает». Капли вытянуты
  вдоль падения и наклонены ветром, снежинки покачиваются; и те и другие
  освещаются небом вдоль собственного луча взгляда, поэтому темнеют к вечеру
  сами. В дождь грядки поливаются сами.
- **Кроны деревьев** собраны из десятка неровных лиственных масс вокруг концов
  веток, а не из одного шара на палке: силуэт рваный, ветки просматриваются,
  низ кроны затенён запечённо в вершинных цветах. У ёлок ярусы с лопастями.
- **Сезоны видно по листве**: цвет деревьев и кустов меняется от свежей
  весенней зелени к золотой осени и выстывшей зиме.

### Интерфейс

- **Главное меню** с медленным облётом фермы на фоне: новая игра, продолжить
  (если есть сохранение), список сохранений, настройки звука, достижения,
  выход. Подпись каждой кнопки **меряется и подгоняется под её рамку**: строка
  слота вроде «Автосохранение — День 3 · Весна · 240 мон. · 0 мин» вылезала за
  край на треть своей длины. Список из восемнадцати достижений раньше уходил
  за нижнюю границу экрана — было видно первые шесть; теперь он на собственной
  подложке, которая считается по длине списка, а не подобрана на глаз.
- **Цены — отдельной колонкой.** В лавке и у котла цена дописывалась к названию
  через пробелы до фиксированной ширины. В моноширинном шрифте это выравнивает,
  в пропорциональном — нет: каждая цена начиналась со своего места. Теперь
  названия и цены — два текстовых узла, строка в строку.
- **Меню паузы**: слева всё управление, справа содержимое сумки, внизу сетка
  кнопок 3×2 — продолжить, сохранить в выбранный слот, настройки, пропустить
  обучение, в главное меню, выйти. Кнопка «пропустить обучение» исчезает, когда
  обучение уже пройдено или отключено: кнопка, которая ничего не делает, хуже,
  чем её отсутствие. Раньше кнопок был один ряд из шести, каждая подпись
  вылезала за свою рамку в соседнюю, а список управления уходил под них — в
  smoke-тесте теперь есть проверка, которая на старой вёрстке падает.
  *Кнопка «Настройки» из этого меню запирала игру* — первый баг, найденный
  живым игроком: она закрывала панель паузы, но не снимала саму паузу, и после
  выхода из настроек WASD, мышь и `E` отказывались работать, а на экране не
  было ничего, что бы это объясняло. Теперь настройки, открытые из паузы,
  возвращают в паузу, открытые по `O` в игре — сразу в игру; проверка
  «настройки не запирают игру» проходит весь этот путь и на старом коде падает.
- **Журнал из трёх разделов** (`←` `→` между ними). *Задания* — цели и
  достижения. *Справочник* — все пять культур (сезон, срок роста, урожай, цена
  семян и продажи) и все семь видов рыбы (цена за килограмм, размер, часы клёва,
  сезоны, сколько раз тянуть), пойманные помечены. Раньше эти числа существовали
  только в коде: игрок не мог узнать, что тыква растёт четыре дня, иначе чем
  посадив её. *Статистика* — день, время за игрой, заработано всего, собрано,
  приготовлено, поймано и самый крупный улов.

### Игровой процесс

- **Пять культур** — патиссон, морковь, томат, пшеница, тыква. У каждой свои
  сезоны, скорость роста, жажда и цена.
- **Грядки живут**: вода и питание убывают, без них растение вянет и погибает.
  Ухоженное растение даёт больше урожая.
- Копать грядки можно **где угодно** на ровной земле, а не только в одной точке.
- Колодец и пруд — источники воды; лейка имеет ёмкость, золотая лейка втрое
  больше.
- **Рыбалка на восемь видов рыбы.** Что клюнет, зависит от часа и сезона:
  форель берёт на рассвете, щука выходит в сумерках, сом — ночной, а плотва
  клюёт всегда. Изредка попадается золотая рыбка, регулярно — старый сапог.
  Размер случаен со смещением к мелочи, цена считается за килограмм, так что
  крупный экземпляр — событие. Пойманное записывается в журнал.
- **Вываживание требует рук.** Сначала короткое окно на подсечку, потом метка
  ходит по шкале, и её нужно несколько раз остановить в зелёной зоне. У редкой
  рыбы зона уже, метка быстрее и тянуть нужно дольше; три промаха — сорвалась.
  Зачарованная удочка замедляет метку, расширяет окно подсечки и поднимает шанс
  на редкую добычу.
- **Лавка** с семенами, удобрением и тремя улучшениями.
- **Живность**: кур и коров можно кормить пшеницей — сытые несут яйца и дают
  молоко. Над готовым животным висит значок; забрать — `E`. **Корм тратится
  только пока животное работает**: раньше он сгорал и тогда, когда продукт уже
  готов и ждёт, так что накормить амбар и уйти на рыбалку значило вернуться к
  половине яиц, за которые заплачена пшеница. Одна пшеница даёт курице два
  яйца (18 монет) независимо от того, стоите вы рядом или нет; сама пшеница
  обходится примерно в монету.
- **Готовка** у котла (`K`): пять рецептов — хлеб, омлет, уха, патиссоновая
  икра, тыквенный пирог. Блюда стоят в разы дороже сырья (тыква — 88 монет,
  пирог из неё — 320) и восстанавливают силы, если их съесть.
- **Задания и достижения** в журнале — девять заданий и одиннадцать достижений.
  *Награды пересчитаны под экономику*: они назначались до двух перебалансировок
  и успели обесцениться — «Первый патиссон» платил 40 монет при цене патиссона
  52, «Кондитер» — 260 за пирог, который сам продаётся за 320. Правило теперь
  простое и закреплено проверкой: премия не меньше рыночной цены того, что
  задание празднует, и растёт вдоль цепочки (70/80/150/150/260/90/110/180/400).
- **Сохранение** в `~/.patisson2/save.json`.

## 🗂 Структура

```
patisson2/
  app.py              игровой цикл, ввод, взаимодействия
  config.py           пресеты качества и настройки мира
  engine/
    pipeline.py       рендер-пайплайн: свет, тени, буферы, постобработка
    shaderlib.py      загрузка GLSL с #include и #define
    shaders/          все шейдеры (небо, сцена, ландшафт, трава, вода, пост)
  world/
    terrain.py        генератор высот и меша земли
    water.py          поверхность пруда
    grass.py          меш травинки + инстансинг
    world.py          сборка мира, маска вскопанной земли
    props.py          расстановка моделей, животные
    daynight.py       часы, солнце, времена года
  game/
    player.py         движение и взаимодействие
    farming.py        культуры, грядки, рост
    state.py          инвентарь, деньги, задания, достижения, сохранения
    npc.py            жители и их распорядок
  audio/
    synth.py          осцилляторы, огибающие, фильтры, реверб
    bank.py           определения всех звуков, фонов и музыки
    manager.py        кэш, воспроизведение, кроссфейды, шаги
  ui/hud.py           интерфейс
  tools/
    meshkit.py        процедурное моделирование + запись .glb
    make_assets.py    определения всех моделей
    shots.py          съёмка скриншотов
assets/models/        38 сгенерированных .glb
```
